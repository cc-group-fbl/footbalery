# Электронные протоколы Footbalery

## Текущая реализация

Миграция `supabase/migrations/20261120_match_protocols.sql` создаёт отдельные таблицы назначений и протоколов. Внешний ключ `match_id` имеет тип `bigint`, как и `public.matches.id`.

RPC-функции:
- `admin_assign_match_referee(bigint, uuid)` — назначение судьи администратором на матч;
- `submit_match_protocol(bigint, ...)` — отправка протокола только назначенным судьёй;
- `admin_review_match_protocol(uuid, text, text)` — одобрение или возврат протокола на исправление. При одобрении счёт атомарно записывается в `matches.score_home` и `matches.score_away`.

## Доступ

- Назначение и проверка протокола доступны только профилю с ролью `admin`.
- Судья видит только собственные назначения и протоколы.
- Судья отправляет протокол только для матча, на который назначен.
- Изменение статуса проверки выполняется через защищённую RPC-функцию.
- Счёт — неотрицательные целые числа; оценки судей — от 0 до 10.
- В клиентском коде используется только publishable/anon key. Service-role key не используется.

## Установка SQL

SQL уже был успешно выполнен в Supabase SQL Editor. Файл миграции в репозитории приведён к фактической схеме с `match_id bigint`. Если разворачивать проект с нуля, выполнить этот файл целиком в SQL Editor.

Важно: если таблицы уже созданы, повторный запуск `CREATE TABLE IF NOT EXISTS` не меняет существующую структуру. Не запускать миграцию повторно для исправления уже существующей таблицы без отдельного плана миграции.

## Синхронизация результата

Миграция `supabase/migrations/20261120_sync_approved_protocol_scores.sql` обновляет RPC проверки. При одобрении счёт из протокола записывается в основную запись `matches`; расписание уже читает счёт из этой таблицы через `schedule_events.match_id`. Миграция также синхронизирует ранее одобренные протоколы. Если эта миграция ещё не выполнена в Supabase, одобрение будет менять только статус протокола.

## Интерфейс

Интерфейс протоколов подключается к существующим аккаунтам Footbalery:
1. Администратор назначает судью на конкретный матч.
2. Назначенный судья видит матч и отправляет электронный протокол.
3. Администратор проверяет протокол, одобряет его или возвращает на исправление с комментарием.

Загрузка файлов протокола пока отключена: для неё потребуется отдельное приватное хранилище и политики доступа.

## Интеграция с Memento

Одобрение протокола пока не означает автоматическую запись в Memento Database. Данные хранятся в Supabase; для передачи в Memento нужен отдельно проверенный безопасный мост (например, через Mini App), без публикации секретного service-role key в клиенте.

## Управление протоколами администратором

Миграция `supabase/migrations/202611240001_protocol_management.sql` добавляет:
- закрытие и повторное открытие назначения протокола; закрытый протокол нельзя отправить или изменить судье;
- удаление отправленного протокола администратором; назначение судьи при этом сохраняется, поэтому судья может заполнить протокол заново;
- если удаляется одобренный протокол, связанные с ним счёт, составы и `protocol_data` очищаются только при совпадении `submission_id` в карточке матча. Несвязанные ручные данные не затрагиваются.

После публикации интерфейса необходимо один раз выполнить SQL-файл миграции в Supabase SQL Editor.
